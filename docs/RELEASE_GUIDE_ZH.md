# CMP 90HX Control 1.2.4

解压整个目录，双击 `CMP90HXControl.exe`。Windows 将在启动时请求一次管理员授权；界面中的后续操作继承同一权限。保留 runtime、drivers、driver、core 子目录及文件清单。

运行环境为 Windows 11 x64、.NET Framework 4.8.1。运行包已包含编译后的工作进程，不需要 Visual Studio、WDK、Python 或 PowerShell 脚本。关闭程序后再次打开会重新请求 UAC。

驱动只允许该发布版本的 Gen2 工作进程调用。其完整 EXE SHA-256 在发布时自动编入驱动，程序本身无需签名；驱动仍需签名。不要混用不同发布包的工作进程和驱动。驱动启动后再启动工作进程，更新已加载驱动需重启。独立诊断程序不在白名单中。

桌面 GUI 重复启动时会恢复并聚焦已打开的窗口，不创建第二个桌面实例；再次启动先尝试唤回窗口，已有 GUI 时无需重复 UAC。SYSTEM 省电进程独立运行，不属于桌面 GUI 单实例范围。

## 使用

1. 打开“驱动管理”：查看构建时选定的一个证书和 CMP90HXDma 的安装状态，按需安装证书和驱动。每次操作后状态自动更新。
2. 点击“环境检查”：检查固定版本文件、签名、核心模拟测试、系统根证书、驱动安装状态、DMA 映射与只读硬件预检。
3. 启动后自动采集一次解锁状态；“刷新解锁状态”可手动重新采集并判断 GPU/上游桥链路与计算、图形解锁值。
4. 环境检查通过后点击“开始解锁”。程序默认使用带就绪检查的快速时序，暂时停用目标显卡。需要长等待时可勾选“保守兼容模式（较慢）”。
5. 原本启用的显卡在允许恢复时重新启用，并读取一次快照验证；原本停用的显卡保持停用，启用后再点击“刷新解锁状态”。

协议 v2 源码整合了原参考驱动的 PCI/MMIO 功能，不再打包 WinRing0/ThrottleStop。必须重新签名 v2 驱动；`build-release.ps1` 自动校验签名、更新工作进程及驱动哈希，再构建 GUI 和打包。可独立运行 `update-release-hashes.ps1` 更新哈希与 GUI。现有 v1 签名文件和历史硬件验证不适用于本次整合。

程序启动后默认自动采集一次快照；刷新解锁状态会确保统一驱动运行，采集快照，不申请 DMA 内存或改变显卡启停状态。状态面板显示本次采集时间，PCIe 是当前协商速率。计算和图形“已解锁”指固定寄存器值符合预期，不代表负载性能或稳定性测试已通过。

排查启动时故障可用 `CMP90HXControl.exe --disable-auto-unlock`，本次桌面启动不自动采集寄存器；与 `--auto-unlock` 同时传入时后台流程直接成功退出。参数只影响本进程，不停用其他后台任务。

要让后续桌面启动及开机/唤醒自动解锁都跳过，在 `C:\ProgramData\CMP90HX\settings.json` 的 JSON 顶层添加 `"DisableAutoUnlock": true`，保留已有 `Power` 等配置项。省略此项或设为 `false` 恢复默认行为；启动参数优先禁用。修改对新启动的进程生效，不中断已开始的硬件操作。手动读取和手动解锁仍可使用，后台省电使用独立的 `Power.Enabled` 设置。

## 核心和时序

使用固定版本核心 469dc0c，SHA256 为 B533B7B245ED606C151CA336B9A6BACEBE935E3EC478246E879C668A4DD98A6A。不是旧的 380bdf3。保守模式每次复位包含 1 秒和 8 秒固定等待；快速模式以配置、链路、BAR 和固件就绪状态决定何时继续，未就绪会报错，不会自动重试解锁。

## 驱动与更新

“驱动管理”打开时及每次操作后，检查 `Cert:\LocalMachine\Root` 中构建时选定的证书。界面显示其实际名称、指纹及安装状态。

构建默认从源码根目录 `cert/` 中读取唯一一个公开 `.cer/.crt` 文件，将名称、SHA-256 和指纹编入 GUI。安装使用随包 `driver/cert/` 中经过上述校验的证书；卸载只移除该指纹对应的证书。其他证书保持原样；卸载后可能无法再次加载当前驱动。

随包的 `driver/CMP90HXDma.sys` 是用户提供、通过 Authenticode 校验的文件。程序安装时再次检查签名和固定哈希。Windows 内核还会执行自身的加载策略；如果拒绝加载，界面显示系统错误码，程序不会自动改变签名策略。

驱动复制到 `%ProgramData%\CMP90HX\DriverStore\<SHA256>\`，创建按需服务 `CMP90HXDma`。安装会清理不再使用的旧版本，正在加载的驱动保留到重启；若当前加载版本与发布包不同，需重启后更新。目录仅允许管理员和 SYSTEM 写入，移动或删除解压目录不会改变服务所用路径。安装自动任务时会先将驱动部署到 DriverStore，后台运行目录只保留程序和核心文件，不再复制 `driver` 和证书目录。

如果已有旧驱动运行，程序拒绝在本次启动中切换；重启后、旧服务未启动时从“驱动管理”安装当前驱动。

“卸载驱动”关闭后续服务启动并删除服务注册，不调用停止驱动。当前驱动没有内核卸载例程；已经加载的驱动、DMA 预留和异常隔离保留到重启。因此运行中的驱动卸载后需重启才能彻底退出。

若日志出现 `DMA_RETAINED`，保持显卡停用并完全关机后重新开机，不直接重试。原生工作进程异常退出后，程序会检查 DMA 所有权再决定能否恢复显卡。运行期间不提供强制中止按钮。

## 计划任务管理

窗口打开时检查 `CMP90HX Auto Unlock` 是否存在，显示启用/运行状态、上次运行时间和结果；提供安装、卸载、手动触发。窗口打开期间每 3 秒刷新。

安装会先校验运行文件，缺少证书时自动安装选定的根证书，缺少驱动时自动安装并启动，再执行完整环境检查。只有全部通过后才注册任务；安装失败会保留具体日志，不反复重试。

任务以 SYSTEM 身份运行，无需登录或重复 UAC。开机及 System 日志 `Microsoft-Windows-Kernel-Power / 107` 唤醒事件直接触发，取消原来的 20 秒和 10 秒固定延迟。事件 42 是进入睡眠，不作为唤醒触发器。后台等待设备枚举最多 30 秒，先检查 DMA 所有权及当前解锁状态；状态符合要求时跳过，未解锁时执行一次并验证一次。自动流程拒绝覆盖已停用的设备。

安装时将完整运行文件复制到受保护的 `%ProgramData%\CMP90HX\AutoUnlock\<version-hash>\`，任务运行该固定位置的副本，移动原解压目录不影响任务。更新程序后点击“安装计划任务”更新后台副本。

重复任务触发采用 IgnoreNew，保留原有硬件操作互斥保护，防止与 GUI 手动操作重叠；全局互斥锁明确允许 SYSTEM 和管理员访问，打开已有对象只请求等待/释放权限。不设置超时杀进程或失败自动重试。卸载任务删除后续触发，不终止当前操作，也不卸载证书或驱动。

安装/更新及卸载任务时，会清理 `%ProgramData%\CMP90HX\AutoUnlock\` 中不再使用的版本副本。仍被任务引用或进程使用的目录保留；桌面 GUI 下次启动时继续清理。无法确定引用或运行状态时暂缓删除，详情记录在日志中。原解压目录、驱动安装目录和省电设置不属于这项清理范围。

唤醒触发器已实现，但 S3/S4/Modern Standby 和快速启动后的实机解锁尚待验证。不要在解锁仍运行、DMA 映射仍使用期间进入睡眠；内核驱动的电源管理实现未改变。

## 空闲省电

打开“空闲省电”，设置 GPU 利用率阈值、连续空闲等待秒数和全速应用例外。默认阈值 15%、等待 10 秒；功能默认关闭，需要点击“启用 / 保存省电设置”。连续低负载且无视频负载时限制到 P8；GPU 利用率达到阈值、检测到视频负载或例外进程运行时立即解除限制，恢复 NVIDIA 自动性能策略。例外填写进程名，如 `game.exe, blender.exe`，支持逗号、分号或换行。

第一次启用前，退出 Inspector 的 **Multi Display Power Saver** 窗口。程序检测到外部省电控制仍运行时会拒绝启用；普通 Inspector 监控窗口可以保留。成功启用会停用已识别的 `\nvidiaInspector\MultiDisplayPowerSaver` 登录任务，保留其程序和配置。停用内置省电后如需恢复 Inspector，可在 Windows 任务计划程序中重新启用其任务。

内置控制通过系统 NVIDIA 驱动提供的 NVAPI 运行，不启动 Inspector 或 PowerShell，不修改电压或超频参数。P8 设置依赖驱动私有接口；驱动不支持时显示错误。界面显示实测 P-state、GPU/视频利用率和可用的 NVML 功耗读数；限制请求成功不保证显卡立即进入 P8，也不保证特定功耗。

启用后注册 `CMP90HX Idle Power Saver`，由 SYSTEM 在开机时常驻运行；关闭 GUI 后继续省电。任务运行 `CMP90HXControl.exe --power-monitor`，入口直接进入后台循环，不创建 WPF Application、界面线程或窗口，也不运行解锁快照、核心自测和工作进程/核心/参考驱动文件检查。仍执行省电所需的设备身份、负载读取和限制恢复；不提供托盘。任务管理器中保留这个独立后台进程是正常现象。

统一设置保存在 `%ProgramData%\CMP90HX\settings.json`，省电设置使用 `Power` 分区，保存时保留其他功能分区。旧 `Power\settings.json` 会自动迁移。后台心跳、当前策略和 P8 限制归属保存在 `State\power-status.json`，旧状态会保留恢复信息迁移，空的旧 `Power` 目录会移除。这是异常恢复需要的运行状态，不应随 `Logs` 日志清理。解锁前确认省电已解除自身限制，再执行显卡操作；解锁后重新枚举显卡，空闲计时重新开始。睡眠恢复通知会重置限制与计时，接口错误时尝试恢复并等待设备重新可用。无法确认恢复时保留限制记录，供下次启动恢复。

“停用并恢复自动性能”等待后台解除限制后移除省电任务，不强制结束进程。使用新版本后，在“计划任务管理”再次安装自动解锁任务以更新原有触发时序；启用省电也会部署新版后台副本。

## 日志

主窗口版本号旁的“一键卸载”先恢复自动性能，再卸载自动解锁、省电计划任务、DMA 驱动服务及本包选定的签名根证书（按编译时记录的指纹从 LocalMachine / Root 移除）。完成后程序退出，已加载驱动在重启后释放。独立的 SYSTEM 清理任务在下次开机清空 `%ProgramData%\CMP90HX`（包含日志、配置、驱动和后台副本），成功后移除自身。目录被占用时会重试；发现链接或驱动重新安装时保留数据。卸载不会删除原解压目录。

1.2.2 统一日志框的滚动区域样式，移除两条滚动条交角处的白色方块，保留横向和纵向滚动。

GUI 和 SYSTEM 任务共用 `%ProgramData%\CMP90HX\Logs\<session-id>\`。每次启动清理此前已结束会话的日志，保留正在运行会话的记录。本次 GUI 各操作在会话子目录下；自动解锁主日志为 `auto-unlock.log`，省电日志为 `power-monitor.log`，达到 1 MiB 后重新开始记录。启动 GUI 同时清理当前用户旧版本 `%LocalAppData%\CMP90HX\logs\` 中的记录。

点击“打开目录”查看当前记录；管理窗口的“打开日志目录”打开共享目录，可查看后台任务记录。“复制”复制界面近期日志。计算、图形和链路的完整快照在 `unlock-status.json` 中。需要长期保存的记录请在下次启动前复制出去。

`files.sha256.json` 用于检查运行文件一致性。DMA 文件已有签名；GUI 与用户态工作进程本身尚未代码签名。

## 验证范围

发布包通过文件、签名、模拟核心、原生工作流恢复路径、环境检查/自动修复顺序、自动解锁分支、两种任务定义、日志清理及模拟省电策略检查，并检查了主窗口和管理窗口布局。省电测试覆盖空闲等待、GPU/视频负载、应用例外、暂停/恢复、设置失败与遗留限制恢复；只读 NVAPI/NVML 探测已读取本机 90HX 数据。验证不自动安装本机计划任务、修改证书或设置真实 P-state。原硬件核心之前已在一台 90HX 上通过 GPU DMA、保守时序解锁以及 Code 0 / Gen2 x16 验证；本次没有重新执行实机完整解锁、P8 写入或睡眠唤醒测试。

1.2.1 增加受限权限互斥锁、任务副本清理/活动租约测试；独立进程窗口激活测试验证最小化窗口恢复与焦点切换；发布包后台入口检查确认未加载 WPF 程序集。更新时先关闭旧桌面 GUI，再启动新版本，在“空闲省电”点击“启用 / 保存省电设置”更新后台；如已安装自动解锁任务，也重新点击“安装计划任务”。
