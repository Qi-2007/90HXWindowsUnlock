# CMP 90HX Control 1.1.0

解压整个目录，双击 `CMP90HXControl.exe`。Windows 将在启动时请求一次管理员授权；界面中的后续操作继承同一权限。保留 runtime、drivers、driver、core 子目录及文件清单。

运行环境为 Windows 11 x64、.NET Framework 4.8.1。运行包已包含编译后的工作进程，不需要 Visual Studio、WDK、Python 或 PowerShell 脚本。关闭程序后再次打开会重新请求 UAC。

## 使用

1. 打开“驱动管理”：查看两个指定证书和 CMP90HXDma 的安装状态，按需安装证书和驱动。每次操作后状态自动更新。
2. 点击“环境检查”：检查固定版本文件、签名、核心模拟测试、两个系统根证书、驱动安装状态、DMA 映射与只读硬件预检。
3. 启动后自动采集一次解锁状态；“刷新解锁状态”可手动重新采集并判断 GPU/上游桥链路与计算、图形解锁值。
4. 环境检查通过后点击“开始解锁”。程序默认使用带就绪检查的快速时序，暂时停用目标显卡。需要长等待时可勾选“保守兼容模式（较慢）”。
5. 原本启用的显卡在允许恢复时重新启用，并读取一次快照验证；原本停用的显卡保持停用，启用后再点击“刷新解锁状态”。

程序启动后自动采集一次快照；刷新解锁状态会使用参考访问驱动采集快照，不启动 DMA 驱动或改变显卡启停状态。状态面板显示本次采集时间，PCIe 是当前协商速率。计算和图形“已解锁”指固定寄存器值符合预期，不代表负载性能或稳定性测试已通过。

## 核心和时序

使用固定版本核心 469dc0c，SHA256 为 B533B7B245ED606C151CA336B9A6BACEBE935E3EC478246E879C668A4DD98A6A。不是旧的 380bdf3。保守模式每次复位包含 1 秒和 8 秒固定等待；快速模式以配置、链路、BAR 和固件就绪状态决定何时继续，未就绪会报错，不会自动重试解锁。

## 驱动与更新

“驱动管理”打开时及每次操作后检查 `Cert:\LocalMachine\Root` 中两个指纹：

- Pikachu Test CA RSA：F57DF00CEB2476C8144B751F1D2D45EDBB3EDFE1
- Pikachu Time Sub CA：671E553BC90A19B26F6F55231E5969F4771976BB

安装使用随包 `driver/cert/` 中经过固定 SHA256 和指纹校验的证书。卸载只移除这两个指纹对应的证书；证书卸载后可能无法再次加载当前驱动。

随包的 `driver/CMP90HXDmaSigned.sys` 是用户提供、通过 Authenticode 校验的文件。程序安装时再次检查签名和固定哈希。Windows 内核还会执行自身的加载策略；如果拒绝加载，界面显示系统错误码，程序不会自动改变签名策略。

驱动复制到 `%ProgramData%\CMP90HX\DriverStore\<SHA256>\`，创建按需服务 `CMP90HXDma`。目录仅允许管理员和 SYSTEM 写入，移动或删除解压目录不会改变服务所用路径。

如果已有旧驱动运行，程序拒绝在本次启动中切换；重启后、旧服务未启动时从“驱动管理”安装当前驱动。

“卸载驱动”关闭后续服务启动并删除服务注册，不调用停止驱动。当前驱动没有内核卸载例程；已经加载的驱动、DMA 预留和异常隔离保留到重启。因此运行中的驱动卸载后需重启才能彻底退出。

若日志出现 `DMA_RETAINED`，保持显卡停用并完全关机后重新开机，不直接重试。原生工作进程异常退出后，程序会检查 DMA 所有权再决定能否恢复显卡。运行期间不提供强制中止按钮。

## 计划任务管理

窗口打开时检查 `CMP90HX Auto Unlock` 是否存在，显示启用/运行状态、上次运行时间和结果；提供安装、卸载、手动触发。窗口打开期间每 3 秒刷新。

安装会先校验运行文件，缺少证书时自动安装两个根证书，缺少驱动时自动安装并启动，再执行完整环境检查。只有全部通过后才注册任务；安装失败会保留具体日志，不反复重试。

任务以 SYSTEM 身份运行，无需登录或重复 UAC。触发器为开机后 20 秒，以及 System 日志 `Microsoft-Windows-Kernel-Power / 107` 唤醒后 10 秒。事件 42 是进入睡眠，不作为唤醒触发器。后台继续等待设备枚举最多 30 秒，先检查 DMA 所有权及当前解锁状态；状态符合要求时跳过，未解锁时执行一次并验证一次。自动流程拒绝覆盖已停用的设备。

安装时将完整运行文件复制到受保护的 `%ProgramData%\CMP90HX\AutoUnlock\<version-hash>\`，任务运行该固定位置的副本，移动原解压目录不影响任务。更新程序后点击“安装计划任务”更新后台副本。

重复任务触发采用 IgnoreNew，保留原有硬件操作互斥保护，防止与 GUI 手动操作重叠；不设置超时杀进程或失败自动重试。卸载任务删除后续触发，不终止当前操作，也不卸载证书或驱动。

唤醒触发器已实现，但 S3/S4/Modern Standby 和快速启动后的实机解锁尚待验证。不要在解锁仍运行、DMA 映射仍使用期间进入睡眠；内核驱动的电源管理实现未改变。

## 日志

GUI 和 SYSTEM 任务共用 `%ProgramData%\CMP90HX\Logs\<session-id>\`。每次启动清理此前已结束会话的日志，保留正在运行会话的记录。本次 GUI 各操作在会话子目录下；后台主日志为 `auto-unlock.log`。启动 GUI 同时清理当前用户旧版本 `%LocalAppData%\CMP90HX\logs\` 中的记录。

点击“打开目录”查看当前记录；管理窗口的“打开日志目录”打开共享目录，可查看后台任务记录。“复制”复制界面近期日志。计算、图形和链路的完整快照在 `unlock-status.json` 中。需要长期保存的记录请在下次启动前复制出去。

`files.sha256.json` 用于检查运行文件一致性。DMA 文件已有签名；GUI 与用户态工作进程本身尚未代码签名。

## 验证范围

发布包通过文件、签名、模拟核心、原生工作流恢复路径、环境检查/自动修复顺序、自动解锁分支、任务定义及日志清理检查，并检查了主窗口与两个管理窗口布局。验证不自动安装本机计划任务或修改证书。原硬件核心之前已在一台 90HX 上通过 GPU DMA、保守时序解锁以及 Code 0 / Gen2 x16 验证；本次没有重新执行实机完整解锁或睡眠唤醒测试。
